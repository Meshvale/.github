# Contributing to Meshvale

Start with the relevant product's README for its current status and capabilities. Use that repository's issues for bugs or feature proposals and its pull requests for changes.

For a reproducible problem, include the version or commit, environment, expected and observed behavior, and a small shareable example. For a feature proposal, explain the use case and expected result. Remove private paths, credentials, and restricted source assets from reports.

Keep a pull request focused on one product concern. Describe what changed, why, and how it was checked. Follow the receiving repository's `ENVIRONMENT.md` for checks appropriate to the change, including documentation, portability, formatting, native tests and installed-binding checks where implemented. Add behavioral tests when implementing a feature.

Original contributions use Apache-2.0 as specified by the receiving repository's LICENSE. Retain third-party license and attribution notices, and identify the license/provenance of any contributed code or fixture. Include only material you have permission to contribute and redistribute.
